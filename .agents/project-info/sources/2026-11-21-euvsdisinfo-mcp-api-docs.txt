EUvsDisinfo MCP Server







MCP server providing access to the EUvsDisinfo database — the largest open registry of pro-Kremlin disinformation cases (19,000+ cases, 6,800+ articles).

Implements Streamable HTTP transport per the MCP specification (2025-03-26+), supporting both stateful mode (with initialize handshake) and stateless mode (one-shot requests without a session — used by the Claude.ai client).

Authentication

The API key can be supplied in three ways (checked in this order):

?key=YOUR_API_KEY                       # query parameter
Authorization: Bearer YOUR_API_KEY      # header
X-API-Key: YOUR_API_KEY                 # header



Without a valid key the server responds with 401 Unauthorized and a JSON-RPC error code -32001.

Two operation modes

The server supports both modes defined by the Streamable HTTP specification. Which one is used depends on the client.

Mode 1: Stateful (with initialization)

The classic three-step MCP flow. This mode is used by MCP Inspector and the official MCP CLI. Session state lives in server memory.

Step 1 — initialize (no mcp-session-id header):

curl -i -X POST "https://mcp.euvsd.info/mcp?key=YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{
    "jsonrpc": "2.0",
    "id": 1,
    "method": "initialize",
    "params": {
      "protocolVersion": "2025-03-26",
      "capabilities": {},
      "clientInfo": {"name": "my-client", "version": "1.0"}
    }
  }'

The server replies with an SSE event and returns the mcp-session-id in the response headers:

HTTP/1.1 200 OK
Content-Type: text/event-stream
mcp-session-id: 037cd3ec-a2bd-4526-97a5-9b0b02941bbc

event: message
data: {"result":{"protocolVersion":"2025-03-26","capabilities":{...}}, "jsonrpc":"2.0","id":1}



Step 2 — tools/list (with the session ID):

curl -i -X POST "https://mcp.euvsd.info/mcp?key=YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -H "mcp-session-id: 037cd3ec-a2bd-4526-97a5-9b0b02941bbc" \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/list"}'

Step 3 — tools/call:

curl -i -X POST "https://mcp.euvsd.info/mcp?key=YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -H "mcp-session-id: 037cd3ec-a2bd-4526-97a5-9b0b02941bbc" \
  -d '{
    "jsonrpc": "2.0",
    "id": 3,
    "method": "tools/call",
    "params": {
      "name": "cases",
      "arguments": {"limit": 10, "offset": 0}
    }
  }'

Step 4 (optional) — DELETE to explicitly terminate the session:

curl -X DELETE "https://mcp.euvsd.info/mcp?key=YOUR_API_KEY" \
  -H "mcp-session-id: 037cd3ec-a2bd-4526-97a5-9b0b02941bbc"
Mode 2: Stateless (no initialization)

This is how the Claude.ai client operates: it does not perform a prior initialize and instead sends its own client-generated mcp-session-id that the server has never issued. In this mode the server spins up an ephemeral transport per request, handles it, and discards the transport.

curl -i -X POST "https://mcp.euvsd.info/mcp?key=YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -H "mcp-session-id: any-client-generated-uuid" \
  -d '{
    "jsonrpc": "2.0",
    "id": 1,
    "method": "tools/call",
    "params": {
      "name": "cases",
      "arguments": {"limit": 10, "offset": 0}
    }
  }'

The server processes the request immediately and returns the result — no session, no state.

Security note. Stateless mode does not preserve correlation between requests, so Last-Event-ID resumability is unavailable. For long-running streams and resumable scenarios, use stateful mode.

Connecting from Claude.ai

Settings → Connectors → Add custom connector

URL: https://mcp.euvsd.info/mcp?key=YOUR_API_KEY

Transport: Streamable HTTP (auto-detected)

Save — done.

Once connected, all four tools are available: cases, articles, search, narratives.

Implementation notes

The server is based on the official @modelcontextprotocol/sdk (TypeScript) example, with two important patches required for compatibility with Claude.ai:

Accept header normalization. A middleware adds the missing MIME types before request handling — the Claude.ai client sends only application/json, while the SDK requires both application/json and text/event-stream.

Stateless fallback. When a request arrives with an unknown mcp-session-id and is not an initialize request, the server creates an ephemeral StreamableHTTPServerTransport with sessionIdGenerator: undefined (the SDK's stateless mode), processes the single request, and disposes of the transport. This is necessary because the Claude.ai client never performs the initialize handshake.

Without these two patches, the official MCP server example does not work with Claude.ai — it returns either 406 Not Acceptable or 400 Bad Request: No valid session ID.
