# 011: admin panel with one analytics page, aggregates only
Date: 2026-11-21 · Status: decided (the user asked for the panel and light-only; the agent chose the data, privacy and auth details below)
Context: the user wanted an admin panel with one page, "Analityka": what people check by hour, day, week and month, how often each topic turns out true or false, and a few extra stats the jury will value, without clutter. A "Dane przykładowe" switch must show the page without real data.
Decision:
- **Page** `/admin/analityka` (`/admin` redirects there), light theme only (user: "nie chce dark/light mode"; `<html data-theme="light">` opts the page out of the dark tokens), `noindex`. Blocks, top to bottom (cut down by the user, 2026-11-21): 3 stat tiles (checks; "Kanały" = share of checks from Discord, Web and Messenger, whole percents that always add up to 100 (largest remainder), the channel name small under each, replacing "Fałszywe lub mylące" at the user's request 2026-11-22; median response time); "Tematy" = the most checked repeated claims as a ranked table (masked claim text, the most common verdict as a pill, 12-slice trend with a tiny hover popover naming the slice and its count, change vs the previous period, check count); then the weekday × hour heatmap and traffic over time ("Ruch") side by side in one row. Removed by the user: "Werdykty według tematu" (verdict mix per claim type), "Bezpieczeństwo i rzetelność", the separate "Najczęściej sprawdzane" list (merged into "Tematy") and the claim-type topic table, the "Sprawdzone zdania" tile (too close to "Sprawdzenia") and the "Koszt 100 sprawdzeń" tile from the UI (the API report still carries `topics`, `integrity` and `channels`). Without the key the page is a full-screen lock (key field + "Pokaż dane przykładowe"); nothing else shows until the key or sample data opens it. Range and sample switches replay a short staggered fade-and-rise (≤0.3 s, off under reduced motion; user: "nice but don't overdo it").
- **Second page `/admin/dokumenty`** (user, 2026-11-21): simple cards for our submission files, each with a scaled-down live iframe preview, "Otwórz ↗" and an optional download link. One entry per file in `apps/web/src/lib/admin/documents.ts`; a Google Sheets/Docs/Slides/Drive link gets its embed URL derived (the file must be shared "anyone with the link can view"), a file in `public/` is previewed directly. The first card is the [cost sheet](../hackathon/deliverables.md) (hosted Google Sheet, no local copy: user, 2026-11-21); the deck and PDFs are meant to follow (user). Static page, no key lock (it holds only links, no data).
- **Topic = the claim `type`** from extraction (numeric, legal, parliamentary, official statement, event, narrative; opinions and untyped claims fall under "Opinie i bez kategorii"), not a free-form keyword model: it exists already, it is stable and it is explainable.
- **Ranges**: 24 h and 7 days (hourly), 30 days (daily), 90 days (weekly), a year (monthly), in Europe/Warsaw time. Edge buckets are flagged `partial` and drawn dashed, so a cut-off month is not read as a drop.
- **One pure function** `buildAnalytics()` in `@prawdowid/core/analytics` builds the report on the server (`GET /api/v1/admin/analytics`) and, on synthetic logs, in the browser for sample mode (`?test=true` or the switch: no API call, no token). Sample logs are clearly invented and deterministic per hour.
- **Privacy**: the check log row now also holds each claim's masked text, type, class and a context-match flag. Claim text is derived from the masked question, so it stays in the deletable store only and is **stripped from the host audit line** (hard constraint 12). The endpoint returns counts plus the masked text of claims asked at least twice: no session ids, no raw input, nothing per person.
- **Auth**: the same `ADMIN_TOKEN`. The admin page sends it as `Authorization: Bearer` from the browser, so CORS now allows the `Authorization` header (origins are still limited to `WEB_ORIGINS`). The token lives in `sessionStorage`, for that tab only.
- **Charts** are hand-built SVG/HTML (no chart library): one hue (navy) for volume, verdict colours for verdicts only, in an order checked by the dataviz palette validator for colour-blind and normal-vision separation (potwierdzone, nie podlega weryfikacji, wprowadzające w błąd, brak dowodów, fałszywe). System states are never a segment in the verdict bars (constraint 8). Every chart has a table view.

Rejected: a chart library (a new dependency for 4 chart types); keyword or embedding topic clustering (not explainable, costs LLM calls); the token only server-to-server (the page could not work); keeping claim text in the host log (not deletable per session).

- **Repeated claims group by wording, not exact text** (user, 2026-11-22: "lewandowski sprzedaje prezerwatywy" and "Czy Robert Lewandowski sprzedaje prezerwatywy?" must count as one): word stems (first 6 letters, diacritics folded, "czy"/hearsay words dropped); two claims are one when the shorter one's stems are ≥80% in the longer one and the overlap is ≥50% of all stems. A negation ("nie") or different numbers always keep them apart. The newest wording is shown. No LLM or embeddings (still explainable, free).
- **Channel split**: the bot sends `platform` (discord, messenger, whatsapp) next to `channel: "messaging"`; the log row keeps it. WhatsApp and old rows without a platform are left out of the tile, so its three shares sum to 100%.
- **Check log in Deno KV** (2026-11-22): the in-memory store saw only the checks of the one isolate that answered the admin call and lost them on every restart or redeploy, so the page showed 1 check after many. `apps/api/check-store.ts` keeps rows in KV (same pattern as source controls, expiry = retention); memory remains the fallback, and only then an ⓘ popover next to the title says so (same as on Źródła; user, 2026-11-22: it shows only when Deno KV is not set up).

Known limit: real data reaches back 30 days (log retention, decision 001; the log is in Deno KV until Supabase lands), so the 90-day and yearly views show real data only for the last 30 days. The page says so.
